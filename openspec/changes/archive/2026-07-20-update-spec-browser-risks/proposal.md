# Proposal: update-spec-browser-risks

## Why

Explore-сессия по SPEC.md v2.0 нашла четыре браузерных риска, которые спека либо не упоминает, либо описывает неточно. Все четыре бьют по этапам 3–4 плана реализации — зафиксировать их нужно до начала кода, иначе решения будут приниматься ad-hoc посреди реализации.

## What Changes

- **Минимальная версия Safari**: `OffscreenCanvas` с 2D-контекстом появился только в Safari 16.4 — воркер-пайплайн (§6.2) на более старых iOS не работает вообще. Спека фиксирует явный минимум: **iOS Safari 16.4+**, без fallback-ветки (осознанное решение, а не умолчание).
- **Память как функция настроек**: §2 называет формат/DPI/качество «чисто UI-параметрами» — это неверно. Они определяют бюджет памяти: 200 страниц при 300 DPI → пик ~1–1.5 ГБ на `save()` → смерть вкладки на телефоне. Спека получает формулу бюджета памяти и мягкий кап DPI на мобильных устройствах.
- **Fallback скачивания на iOS**: `<a download>` с большим Blob исторически ненадёжен на iOS Safari. Добавляется требование fallback через Web Share API (`navigator.share({files})`, iOS 15+).
- **Ранний тест EXIF-ориентации**: `createImageBitmap(..., {imageOrientation: 'from-image'})` в Safari поддержан поздно и криво — ручной тест на реальном iPhone переносится с этапа 6 на этап 3 (DoD этапа 3 дополняется).

Изменения — только в SPEC.md и в OpenSpec-спеках; кода в проекте ещё нет, ничего не ломается.

## Capabilities

### New Capabilities

- `browser-compat`: требования совместимости и границ браузерной платформы — минимальные версии браузеров, бюджет памяти генерации PDF (кап DPI на мобильных), fallback доставки готового PDF, момент верификации EXIF-ориентации.
