# canvas-pipeline — delta

## ADDED Requirements

### Requirement: Источники файлов
Приложение SHALL принимать изображения через drag&drop (зона сканера и состояние сетки), клик по кнопкам добавления (системный файловый диалог, множественный выбор) и на мобильных — через системный выбор камера/галерея (`<input type="file" accept="image/*" multiple>` без `capture`).

#### Scenario: Drag&drop на десктопе
- **WHEN** пользователь перетаскивает три JPEG-файла на зону сканера
- **THEN** в сетке появляются три карточки в состоянии обработки, затем миниатюры

#### Scenario: Мобильный выбор
- **WHEN** пользователь на телефоне нажимает кнопку добавления
- **THEN** открывается системный диалог с выбором между камерой и галереей

### Requirement: Детект формата и отказ по HEIC
Каждый файл SHALL проверяться снифом первых байт (`sniffFormat`) в дополнение к `file.type`. HEIC-файл SHALL получать карточку ошибки с текстом про режим передачи «Автоматически» на iPhone и SHALL NOT обрабатываться дальше. Нечитаемый или неподдерживаемый файл SHALL получать карточку ошибки «Не удалось прочитать файл». Карточки ошибок удаляемы и SHALL NOT попадать в генерацию.

#### Scenario: HEIC отклонён с подсказкой
- **WHEN** добавлен файл с ISOBMFF-сигнатурой и брендом `heic`
- **THEN** карточка переходит в состояние ошибки с подсказкой про iPhone, декодирование не выполняется

#### Scenario: Повреждённый файл
- **WHEN** добавлен файл с сигнатурой JPEG, но не декодируемый `createImageBitmap`
- **THEN** карточка переходит в состояние ошибки «Не удалось прочитать файл», остальная очередь продолжает обрабатываться

### Requirement: Декодирование с EXIF-ориентацией
Декодирование SHALL выполняться через `createImageBitmap(file, {imageOrientation: 'from-image'})` — с явной опцией, не полагаясь на дефолт браузера. Сохранённые размеры изображения SHALL соответствовать видимой (после EXIF-поворота) ориентации.

#### Scenario: Портретное фото с iPhone
- **WHEN** добавлено портретное JPEG-фото с EXIF orientation 6 (камера iPhone)
- **THEN** миниатюра отображается вертикально без ручного поворота, сохранённые width < height

### Requirement: Миниатюры и последовательная обработка
Для каждого принятого файла SHALL строиться JPEG-миниатюра (длинная сторона 320 px, качество 0.8), доступная через blob URL. Файлы SHALL обрабатываться последовательно — не более одного полноразмерного декодирования одновременно. Исходный `ImageBitmap` SHALL закрываться сразу после построения миниатюры; в памяти очереди остаются только `File` и миниатюра.

#### Scenario: Пачка из 30 фото
- **WHEN** добавлено 30 фото по 12 МП
- **THEN** карточки получают миниатюры по очереди, UI остаётся отзывчивым, одновременно декодируется не более одного полноразмерного изображения

### Requirement: Освобождение памяти миниатюр
При удалении карточки и при очистке очереди SHALL вызываться `URL.revokeObjectURL` для blob URL миниатюры.

#### Scenario: Удаление карточки
- **WHEN** пользователь удаляет карточку из сетки
- **THEN** blob URL её миниатюры отозван

### Requirement: Лимиты очереди
При превышении 100 файлов в очереди UI SHALL показывать предупреждение о возможной нехватке памяти. Файлы сверх 200 SHALL отклоняться с сообщением; уже принятые SHALL сохраняться.

#### Scenario: Предупреждение
- **WHEN** в очереди становится 101 файл
- **THEN** отображается предупреждение о лимитах памяти устройства

#### Scenario: Потолок
- **WHEN** в очереди 200 файлов и пользователь добавляет ещё 5
- **THEN** новые файлы отклонены с сообщением, очередь остаётся из 200

### Requirement: Вендоринг без CDN
Все JS-зависимости UI (`alpine.esm.js`, `sortable.min.js`) SHALL загружаться из `web/vendor/`; внешних (CDN) ссылок в разметке SHALL NOT быть.

#### Scenario: Офлайн-LAN
- **WHEN** страница открыта с устройства без доступа в интернет (только LAN до сервера)
- **THEN** UI полностью функционален: реактивность, drag-reorder, стили

### Requirement: Реальный прогресс вместо симуляции
Состояние «обрабатывается» на карточке SHALL отражать фактическую обработку файла (до готовности миниатюры), таймерные симуляции прогресса из прототипа SHALL быть удалены. Симуляция генерации PDF (`startGenerate`) остаётся до этапа 4 и SHALL быть помечена в коде как заглушка.

#### Scenario: Карточка отражает реальность
- **WHEN** файл добавлен и его обработка завершилась
- **THEN** карточка переходит из состояния обработки в готовую миниатюру в момент фактической готовности, без таймеров
