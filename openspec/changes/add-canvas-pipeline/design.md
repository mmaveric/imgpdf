# Design: add-canvas-pipeline

## Context

Прототип (`docs/prototype.html`, после этапа 5 — копия в `web/index.html`) содержит рабочий Alpine store (~60 строк, `prototype.html:443-504`): состояния empty/grid/result, reorder через SortableJS (`delayOnTouchOnly:true, delay:150` — уже решено), оптимистичный rotate, настройки. Мокнуты две вещи: добавление файлов (`addMock` — цветные заглушки с фейковым прогрессом) и генерация (`startGenerate` — setTimeout-цепочка). Этот change заменяет первую; вторая остаётся до этапа 4. Файловых input в прототипе нет, SortableJS грузится с CDN.

## Goals / Non-Goals

**Goals:**

- Реальные файлы проходят до сетки миниатюр: drag&drop, клик, камера/галерея.
- EXIF-ориентация корректна на целевых браузерах (DoD — реальный iPhone).
- Никаких CDN — vendored Alpine + SortableJS.
- Память под контролем: revoke, лимиты, ImageBitmap не живут дольше необходимого.

**Non-Goals:**

- Генерация PDF — этап 4 (`startGenerate` остаётся симуляцией).
- pdf-lib вендоринг — этап 4.
- HEIC-декодирование — только детект + карточка ошибки (v1.1, SPEC §13).

## Decisions

### D1. Нарезка: index.html + styles.css + app.js, vendor локально

Разметка и стили переносятся 1:1 (дизайн закрыт, SPEC §8). Store уезжает в `web/app.js` (ESM). Alpine — vendored ESM-сборка (`alpine.esm.js`), инициализация `Alpine.data('app', ...)` + `Alpine.start()` вместо auto-init через CDN-скрипт. SortableJS — vendored `sortable.min.js`. Версии фиксируются комментарием в первой строке vendor-файла (имена файлов уже заданы SPEC §5.1 — не переименовываем, кеш-правило «новая версия = новое имя» вступит при первом реальном обновлении).

### D2. В памяти живёт File, не ImageBitmap

После построения миниатюры исходный `ImageBitmap` закрывается (`bitmap.close()`), в записи изображения остаётся исходный `File` + blob URL миниатюры. Генерация (этап 4) декодирует заново по требованию — последовательно, по одному. Альтернатива (держать ImageBitmap всех фото) — сотни МБ на очереди из 50+ снимков, ровно тот сценарий смерти вкладки из §6.3. Цена — повторный decode на генерации, это секунды на фоне минут самой генерации.

### D3. pipeline.js — модуль ingest, app.js — только glue

`web/pipeline.js` (ESM) экспортирует `async ingestFile(file) => {ok, thumbUrl?, width?, height?, error?}`:

1. `sniffFormat(await первые 16 байт)` (из `pipeline-math.js`) + `file.type` — HEIC → `{ok:false, error:'heic'}`, unknown+нечитаемый → `{ok:false, error:'unsupported'}`.
2. `createImageBitmap(file, {imageOrientation:'from-image'})` — decode-ошибка → `{ok:false, error:'corrupt'}`.
3. Canvas thumbnail: длинная сторона 320px → `toBlob('image/jpeg', 0.8)` → `URL.createObjectURL`.
4. `bitmap.close()`, вернуть размеры оригинала (уже с учётом EXIF-поворота).

`app.js` заменяет `addMock`: карточка создаётся сразу (`uploading:true`), файлы обрабатываются последовательно через одну очередь-промис (не `Promise.all` — декодировать по одному, §6.3), по завершении карточка получает thumbnail или состояние ошибки. Прогресс на карточке — бинарный (обрабатывается/готово): реальные стадии decode/resize не дают промежуточных процентов, симуляция таймером убирается.

### D4. Источники файлов

Один скрытый `<input type="file" accept="image/*" multiple>` + программный `click()` с существующих кнопок прототипа. На мобильных `accept="image/*"` даёт системный выбор камера/галерея — отдельный `capture` не ставим (отнял бы выбор галереи). Drag&drop: `dragover`/`drop` на scan-bed и на всей странице в состоянии grid, из `DataTransfer` берутся только `File` с образом `image/*` или проходящие сниф.

### D5. Карточка ошибки

`{ok:false}` не выкидывает карточку, а переводит в состояние ошибки с текстом: HEIC — «HEIC не поддерживается — на iPhone включите передачу „Автоматически“» (§6.1 п.2), corrupt/unsupported — «Не удалось прочитать файл». Карточка удаляема, в генерацию не попадает (этап 4 фильтрует `ok`).

### D6. Память и лимиты

- `removeImage`/`clearAll` делают `URL.revokeObjectURL(thumbUrl)` — прямое требование §10.
- Предупреждение в UI при > 100 файлов в очереди, жёсткий потолок 200 (новые файлы сверх — отклоняются с сообщением). Числа из §6.3.
- Один переиспользуемый thumbnail-canvas на модуль, а не новый на каждый файл (лимит суммарной canvas-памяти Safari, §10).

### D7. Feature-detect при старте

`typeof OffscreenCanvas === 'undefined'` → полноэкранное сообщение «браузер не поддерживается, нужен iOS 16.4+ / актуальный браузер», UI загрузки скрыт (требование browser-compat). Детект именно OffscreenCanvas, хотя этап 3 её не использует: платформа объявлена единым минимумом, нет смысла впускать пользователя, который упрётся на генерации.

### D8. Тестирование — ручное, по матрице

Логика, которую можно тестировать без браузера, уже в `pipeline-math.js` (сниф — там). `pipeline.js` — тонкая обёртка над браузерными API, юнит-тестировать нечего без DOM-моков, которые проверяли бы моки. DoD: ручная матрица — десктоп Chrome/Firefox (drag&drop, клик, повреждённый файл, HEIC-фикстура) + реальный iPhone по LAN (галерея, камера, портретное EXIF-фото, оба режима передачи HEIC).

## Risks / Trade-offs

- [Повторный decode на генерации (D2)] → секунды против сотен МБ памяти; осознанный размен, зафиксирован в SPEC §6.1 п.5 как допустимый вариант.
- [Бинарный прогресс карточки вместо процентов] → честнее фейковых процентов прототипа; визуально карточка живёт (спиннер/шиммер), UX не хуже.
- [Alpine ESM-инициализация отличается от CDN-автостарта] → одна строка `Alpine.start()`; проверяется первым же открытием страницы.
- [Drag&drop директорий/не-файлов] → фильтр по `File` + сниф; мусор даёт карточку ошибки, не исключение.

## Migration Plan

`web/index.html` переписывается с копии прототипа на настоящую разметку — прототип остаётся нетронутым в `docs/`. Откат — вернуть копию прототипа.
