# Design: add-brand-home-reset

## Context

`clearAll()` в `web/app.js` уже делает почти весь сброс: revoke миниатюр, очистка `images`, `limitMsg`/`genError`, `view='empty'`, закрытие настроек, `releasePdf()`. Не хватает остановки активного воркера (`_worker`) и сброса `job` — при клике во время генерации воркер продолжит молотить и пришлёт `done`/`error` в уже сброшенное состояние. `.brand` — `<div>` в `header.app-header`.

## Goals / Non-Goals

**Goals:**
- Один клик по логотипу = гарантированно чистый старт из любого экрана, включая активную генерацию.
- Никаких утечек: objectURL миниатюр и PDF освобождены, воркер убит.

**Non-Goals:**
- Сброс настроек PDF (предпочтения переживают сессию).
- Диалог подтверждения — в шапке уже есть «очистить» без подтверждения, поведение консистентно.
- Роутинг/URL-навигация: приложение одностраничное, «главная» = экран empty.

## Decisions

### D1. `goHome()` = terminate воркера → `clearAll()` → сброс `job`

Отдельный метод, а не расширение `clearAll()`: «очистить» в шапке видна только на grid-экране (генерации нет), терминация воркера там лишняя; логотип же кликабелен всегда. `_worker?.terminate(); _worker = null;` до `clearAll()` — гарантия, что поздние `onmessage` не переключат view. `job = {done:0,total:0,finished:false}` — чтобы повторный заход на result-экран не показал старое состояние.

### D2. `.brand` — семантика кнопки

`<div class="brand">` получает `@click="goHome()"`, `role="button"`, `tabindex="0"` и `@keydown.enter="goHome()"`; в CSS — `cursor:pointer`. Замена div на `<button>` потянула бы пересброс стилей шапки — не стоит того.

## Risks / Trade-offs

- [Случайный клик по логотипу стирает очередь] → консистентно с существующей «очистить»; очередь восстанавливается повторным выбором файлов. Подтверждение — backlog, если начнёт мешать.
- [Гонка: `done` прилетает в тик клика] → `terminate()` синхронен; после него сообщения не доставляются.
