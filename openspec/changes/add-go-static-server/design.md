# Design: add-go-static-server

## Context

SPEC.md §5 описывает Go-часть исчерпывающе: один файл, стандартная библиотека + `go-qrcode`, ни одного API-роута. Кода в репозитории нет вообще — это первый change с кодом. Web-слоя тоже нет, но серверу нужно что-то раздавать; кликабельный прототип `docs/prototype.html` самодостаточен (Alpine/SortableJS, судя по SPEC §8 — рабочие состояния) и годится как временное наполнение `web/`.

## Goals / Non-Goals

**Goals:**

- Рабочий `imgpdf`-бинарник: раздаёт `web/` по LAN, печатает адреса и QR, `--dev` для живой правки.
- `web/index.html` = копия прототипа, чтобы с телефона сразу открывалось что-то реальное.
- Обновить порядок этапов в SPEC.md §12 (этап 5 → сразу после этапа 1).

**Non-Goals:**

- Нарезка прототипа на `app.js`/`styles.css`/`pipeline.js` — этап 3.
- Makefile и кросс-компиляция — этап 6.
- Любые API-роуты, TLS, авторизация — вне архитектуры (§5.2).

## Decisions

### D1. Один main.go, embed + fs.Sub

`//go:embed web` в корне модуля + `fs.Sub(embedded, "web")` → `http.FileServer(http.FS(sub))`. Embed-директива требует, чтобы `web/` лежала рядом с файлом, содержащим директиву → embed объявляется в корневом пакете (файл `embed.go` в корне) либо main.go живёт в корне. Решение: `cmd/imgpdf/main.go` (как в SPEC §5.1) + маленький `embed.go` в корне модуля, экспортирующий `web embed.FS`. Альтернатива — символический путь `../../web` в embed — не работает (embed не разрешает `..`).

### D2. `--dev` = os.DirFS

Один флаг переключает источник: `fs.Sub(embedFS, "web")` ↔ `os.DirFS("web")`. Правка файла на диске видна по F5 без пересборки. Никакого live-reload — не нужен.

### D3. Кеш-политика через обёртку Handler

Middleware над FileServer: путь `== /` или `/index.html` → `Cache-Control: no-cache`; префикс `/vendor/` → `Cache-Control: public, max-age=604800` (7 дней — vendor-файлы не хешированы по содержимому, вечный кеш опасен при смене версии библиотеки под тем же именем); остальное (`app.js`, `styles.css` в будущем) → `no-cache`, пока нет версионирования. В `--dev` — всё `no-cache`.

### D4. LAN-адреса и QR

`net.Interfaces()` → интерфейсы с флагом `up`, не loopback → IPv4-адреса → печать `http://<ip>:<port>` для каждого. QR (`go-qrcode`, `qrcode.Medium`, `.ToSmallString(false)`) — один, для первого приватного (RFC 1918) адреса; если таких нет — QR не печатается. Если `--host` задан не-wildcard значением — печатать только его.

### D5. Graceful shutdown

`signal.NotifyContext(SIGINT, SIGTERM)` + `srv.Shutdown(ctx)` с таймаутом 5 с. Для статики это почти формальность, но фиксируется в спеке (§9 требует).

### D6. Тесты — httptest, минимум

Юнит-тесты через `net/http/httptest`: `/healthz` → 200, `/` → 200 + `no-cache`, `/vendor/x` → `max-age`. Логика LAN-фильтрации — отдельная чистая функция `lanAddrs([]net.Addr) []string`, тестируемая без реальных интерфейсов. Ручная проверка с реального телефона — обязательная часть DoD.

### D7. go.mod

Модуль `imgpdf`, Go 1.22+. Единственная зависимость — `github.com/skip2/go-qrcode`.

## Risks / Trade-offs

- [Копия прототипа в `web/` создаёт дубль с `docs/prototype.html`] → временно и осознанно; этап 3 заменит `web/index.html` настоящей разметкой, `docs/prototype.html` останется историческим артефактом.
- [7-дневный кеш vendor может отдать старую библиотеку после релиза с той же ссылкой] → при обновлении vendor-файла менять имя (например, суффикс версии) — зафиксировано как правило в SPEC §5.2 при правке.
- [`0.0.0.0` без авторизации] → принятая модель угроз доверенной LAN (SPEC §9), не расширяем.

## Migration Plan

Новый код, ломать нечего. Откат — удалить `cmd/`, `embed.go`, `go.mod`, `web/`.
