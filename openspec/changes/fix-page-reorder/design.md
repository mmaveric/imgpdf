# Design: fix-page-reorder

## Context

Сетка карточек рендерится Alpine `x-for` внутри `<template x-if="view==='grid'">`; контейнер `#imageGrid` — `<div style="display:contents">`, его первый DOM-ребёнок — сам `<template x-for>`. SortableJS 1.15.2 (UMD, `window.Sortable`) инициализируется один раз из `addFiles` с guard `grid._init`. Три дефекта описаны в proposal.md: отсутствие переинициализации после пересоздания DOM, сдвиг индексов из-за `<template>` в детях, конфликт DOM-мутаций Sortable с keyed-патчем Alpine.

## Goals / Non-Goals

**Goals:**
- Drag-reorder работает всегда, пока виден grid-экран: после возврата с result, после очистки и повторного добавления.
- `oldIndex`/`newIndex` указывают на реальные карточки; массив `images` после drop соответствует видимому порядку.
- Порядок карточек в сетке — единственный источник порядка страниц PDF.
- Конфиг Sortable пригоден для touch (long-press, без конфликта со скроллом).

**Non-Goals:**
- Кнопки автосортировки (по имени/дате) — отдельный backlog.
- Замена SortableJS или самописный drag.
- Анимации/полировка вида ghost-элемента.

## Decisions

### D1. Инициализация через `x-init` на контейнере сетки

`<div id="imageGrid" x-init="initSortable($el)">` — Alpine вызывает `x-init` при каждом монтировании узла, то есть ровно тогда, когда `x-if` пересоздал сетку. `initSortable(el)` принимает элемент параметром; guard `el._init` остаётся (защита от повторного вызова на том же узле — например, `$nextTick` из `addFiles` убирается совсем).

*Альтернативы*: `$watch('view')` + `$nextTick` — работает, но дублирует знание «когда сетка в DOM»; MutationObserver — лишняя машинерия.

### D2. `draggable: '.thumb-card'`

Опция заставляет Sortable считать индексы только среди карточек: `<template x-for>` перестаёт участвовать в нумерации (уходит сдвиг на единицу) и не может быть захвачен как draggable.

### D3. Откат DOM-перестановки в `onEnd` перед мутацией массива

Sortable уже переставил узел в DOM; Alpine при последующем keyed-патче исходит из того, что DOM соответствует прежнему массиву. Паттерн: в `onEnd` вернуть перетащенный элемент на исходную позицию (вставить перед прежним соседом среди `.thumb-card`), затем `splice` массива — Alpine выполняет перестановку сам по чистому DOM.

*Альтернатива*: положиться на keyed-реконсилиацию Alpine поверх мутированного DOM — поведение недокументированное, даёт дубли карточек (наблюдаемый баг).

### D4. Touch-конфиг без изменений, проверка на устройстве

`delay: 150, delayOnTouchOnly: true` — стандартный рецепт SortableJS для мобильных (long-press отделяет drag от скролла). Дефекты D1–D3 платформонезависимы — «не работает на телефоне» объясняется ими же. Отдельный ручной пункт проверки на iPhone вместе с существующим хвостом 4.2 change'а add-canvas-pipeline.

### D5. E2e-верификация порядка через размеры страниц PDF

Фикстуры разного размера (800×600 и 300×500) + `page:'auto'`: после reorder порядок страниц в сгенерированном PDF различим по размерам страниц при парсинге pdf-lib в Node. Проверяет всю цепочку сетка → массив → воркер → PDF, а не только DOM.

## Risks / Trade-offs

- [Playwright drag-эмуляция нестабильна для HTML5 DnD] → SortableJS использует pointer-события, не нативный DnD; `browser_drag` с ним работает. Запасной вариант — прямой вызов `onEnd`-логики не делаем: тогда тест теряет смысл.
- [`x-init` на элементе с `display:contents`] → `x-init` не зависит от layout-модели, вызывается по факту вставки в DOM.
- [Откат DOM в `onEnd` сломается при смене разметки карточки] → селектор `.thumb-card` в одном месте (опция + откат), задача фиксирует связь комментарием.

## Migration Plan

Правки только в `web/app.js` и `web/index.html`; без миграций. Откат — revert коммита.
