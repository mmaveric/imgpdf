# browser-compat Specification

## Purpose

Требования совместимости с целевыми браузерами: минимальная платформа, бюджет памяти генерации, доставка готового PDF и EXIF-ориентация. Источник — change `update-spec-browser-risks` (закрытие рисков SPEC.md v2.1).

## Requirements

### Requirement: Минимальная поддерживаемая платформа
Приложение SHALL поддерживать iOS Safari 16.4+, актуальные Chrome Android и вечнозелёные десктопные Chrome/Firefox/Safari. При запуске в браузере без `OffscreenCanvas` с 2D-контекстом приложение SHALL показать явное сообщение о неподдерживаемом браузере вместо частично работающего UI.

#### Scenario: Неподдерживаемый браузер
- **WHEN** приложение открыто в браузере без поддержки `OffscreenCanvas` (например, iOS Safari 16.3)
- **THEN** пользователь видит сообщение о неподдерживаемом браузере с указанием минимальной версии, интерфейс загрузки файлов недоступен

#### Scenario: Поддерживаемый браузер
- **WHEN** приложение открыто в iOS Safari 16.4+ или актуальном десктопном браузере
- **THEN** приложение работает без предупреждений о совместимости

### Requirement: Бюджет памяти генерации
Настройки страницы (формат, DPI, качество JPEG) SHALL трактоваться как параметры бюджета памяти, а не только UI-параметры. На мобильных устройствах (детект `navigator.userAgentData.mobile` с fallback на UA-строку) эффективный DPI рендера страницы SHALL быть ограничен значением 200.

#### Scenario: Кап DPI на мобильном
- **WHEN** пользователь на мобильном устройстве запускает генерацию с настройкой DPI выше 200
- **THEN** страницы рендерятся с эффективным DPI 200

#### Scenario: Десктоп без капа
- **WHEN** пользователь на десктопе запускает генерацию с DPI 300
- **THEN** страницы рендерятся с запрошенным DPI 300

### Requirement: Доставка готового PDF
Приложение SHALL предлагать скачивание готового PDF через `<a download>` с blob URL. На устройствах, где `navigator.canShare({files})` возвращает true для PDF-файла, приложение SHALL дополнительно предлагать кнопку «Поделиться», открывающую системный share sheet через Web Share API.

#### Scenario: Share sheet на iOS
- **WHEN** генерация завершена на iOS Safari 16.4+
- **THEN** пользователю доступны и ссылка скачивания, и кнопка «Поделиться», открывающая share sheet с готовым PDF

#### Scenario: Десктоп без Web Share
- **WHEN** генерация завершена в десктопном браузере без поддержки Web Share с файлами
- **THEN** пользователю доступна ссылка скачивания, кнопка «Поделиться» не отображается

### Requirement: EXIF-ориентация на целевых браузерах
Миниатюры и страницы PDF SHALL отображать изображение с учётом EXIF-ориентации (`createImageBitmap(file, {imageOrientation: 'from-image'})`) на всех целевых браузерах. Верификация на реальном iOS Safari SHALL входить в DoD этапа Canvas-пайплайна (этап 3), а не финальной полировки.

#### Scenario: Портретное фото с iPhone
- **WHEN** пользователь добавляет портретное JPEG-фото с iPhone (EXIF orientation ≠ 1) в iOS Safari
- **THEN** миниатюра и итоговая страница PDF отображаются в правильной ориентации без ручного поворота
